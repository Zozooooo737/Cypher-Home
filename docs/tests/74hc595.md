- Bus et adressage : GPIO, commande logicielle par `shiftOut()`. Le bus SPI matériel n'est pas utilisé : il est partagé par la caméra et l'écran.
- Éléments ajoutés : aucun sur le registre (résistances des LED : voir `leds.md`).
- Cette table est le câblage **testé** le 2026-11-09. `pins.h` donne le câblage courant, et la table D3 validée fait foi.

## Logiciel

- Bibliothèque : aucune (`shiftOut()` du cœur Arduino Renesas 1.6.0).
- Ligne `lib_deps` : N/A.
- Compatibilité UNO R4 WiFi : oui.
- Fichier du dépôt : `firmware/src/components/leds.cpp` (pas de module propre : le registre ne sert qu'aux LED).
- Paramètres clés : envoi de l'octet en MSBFIRST (bit 0 → QA, bit 7 → QH), puis impulsion sur RCLK.
- Alternatives écartées : bus SPI matériel, partagé avec la caméra et l'écran (une broche CS de plus et un risque de conflit sur le bus).

## Résultat

- Intégrité : fonctionnel ; constat visuel par le test des LED (chaque sortie QB à QE commande la bonne LED).
- Sortie type : voir `leds.md`.

## Pièges et limites

- Le dernier bit envoyé arrive sur QA : décaler la correspondance d'un bit allume les mauvaises LED.
- Non testé : courant total des sorties, tension réelle de VCC.
